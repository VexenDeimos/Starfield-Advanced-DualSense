Date: 2026-09-12

Runtime marker: `0.3.85-music-haptics-recon`

## Scope

v0.3.85 is **Music Haptics Recon only**. It does not generate music haptics.
It passively observes zero-external Wwise events, resolves likely music metadata/media in memory on the existing background `WeaponAudioPipeline` worker, and logs evidence needed to design the production music-authority path.

This test is listening for **metadata and lifecycle evidence**, not controller vibration. A successful recon run must not add music-driven haptics, adaptive-trigger effects, controller-speaker playback, lightbar behavior, whole-game-mix capture, WEM extraction, or changes to Starfield's original audio.

Music Recon uses the existing `PostEvent` interception point only. The Wwise callback performs bounded observation only; archive lookup, structure inspection, and candidate decode probing remain on the existing background audio worker. Recon is enabled by the existing `DebugLogging=true` development setting; there is no production `MusicHapticsEnabled` config key in this release.

## Windows Gate First

Before launching Starfield, run the supplied v0.3.85 Windows build/install gate and send its **complete output** for review. Do not begin the controlled runtime session merely because the DLL builds or installs.

The gate verifies:

- the v0.3.85 runtime/version/source contract;

- the focused Music Recon test wall;
- retained audio-pipeline and resolver/decode targets;
- the affected retained REV-8/ship controller and haptics wall;
- a force-clean Windows/CommonLibSF plugin build;
- built and installed DLL ProductVersion/FileVersion `0.3.85.0 / 0.3.85.0`.

## Controlled Music Recon Session

After the Windows gate output has been reviewed and approved:

1. Launch Starfield and load into ordinary gameplay with DebugLogging=true.
2. Spend ~60 seconds in a quiet exploration area while normal background score plays. Avoid menus and unnecessary weapon fire.
3. Move/explore for ~60 seconds and let at least one natural musical swell or exploration-score transition occur if possible.
4. Enter combat and remain in combat for ~60 seconds. Avoid firing when practical so later log review can correlate combat score without a flood of weapon events.
5. While score is active, open DataMenu for ~15 seconds, close it, then open PauseMenu for ~15 seconds and close it. Recon intentionally remains passive so logs show whether score events continue or transition under menus.
6. If an easy scripted musical transition is available, trigger it once; otherwise skip rather than forcing unrelated gameplay.
7. Quit Starfield normally.
8. Send the complete fresh StarfieldDualSense log. No WEM extraction folder is expected; resolution is in-memory.

## What the Log Must Prove Before Production Music Haptics

Promotion requires evidence of all of the following:

- a stable set of Wwise event names, banks, media, or path metadata correlates with non-diegetic exploration/combat/ambient score;
- likely soundtrack candidates do not merely correlate with weapon, UI, or world-space activity;
- candidate WEM media are structurally valid and report `decodeReady=yes` where needed;
- event/media identity remains understandable across at least one score transition or stem overlap;
- menu observations explain whether score continues or changes while future production music haptics would be muted;
- no Music Recon path produced haptic, trigger, speaker, or lightbar output;
- normal game audio remained untouched.

If the log does not prove a clean score-only `PostEvent` authority path, stop. The next step is targeted Wwise state/switch reconnaissance—not a music analyzer/mixer and not whole-game audio capture.
