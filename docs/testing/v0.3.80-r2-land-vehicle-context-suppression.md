# v0.3.80-r2 — Land Vehicle Context Suppression

## Purpose

This hotfix addresses stale on-foot controller ownership observed during the first
REV-8 reconnaissance run. While `CameraState::kVehicle` was active, the accepted
on-foot Maelstrom R2 wall (`01 7C 82`) could remain installed. REV-8 R2 is the
vehicle gun, so handheld trigger, haptic, and weapon-speaker ownership must not
survive the transition into the vehicle.

`kVehicle` remains **suppression-only corroboration**. This hotfix does not promote
camera state to vehicle identity/authority and adds no REV-8 haptics, adaptive
trigger profile, speaker effect, lightbar effect, weapon-fire authority, motion
authority, boost authority, or physics telemetry.

## Runtime contract

On the first fresh `kVehicle` camera transition while no ship pilot context owns
control, `GameStateAdapter` emits `LandVehicleContextEntered`.

That semantic clears and suppresses on-foot ownership in all three relevant
consumers:

- `EffectsEngine`: handheld weapon profile, adaptive trigger state, transient
  trigger state, and on-foot lightbar ownership are cleared.
- `HapticsManager`: handheld continuous/finite haptic authority and cached R2
  weapon state are cleared/suppressed.
- `WeaponSpeakerPlayback`: active handheld profile and sustained speaker owner are
  cleared/suppressed.

`LoadingMenu` does not release that suppression while the land-vehicle camera
boundary remains active.

When `kVehicle` ends, `GameStateAdapter` emits `LandVehicleContextExited`. Exit
releases the suppression gate but restores no cached handheld state. Plugin-level
fresh-context refresh is requested, so normal on-foot ownership is rebuilt only
from fresh weapon/health observations.

Ship pilot lifecycle remains authoritative over its existing controller ownership.
A ship-pilot takeover clears the land-vehicle suppression boundary internally and
does not fabricate a land-vehicle exit.

## TDD / regressions

`V0380R2LandVehicleContextSuppressionRegression.py` was written first and failed
against v0.3.80-r1 because the two land-vehicle lifecycle semantics and consumer
suppression paths did not exist. It passes after the minimal production change.

`V0380R2LandVehicleContextSuppressionTest.cpp` exercises the complete consumer
contract on Windows:

- pre-vehicle handheld R2 wall is cleared at vehicle entry;
- held REV-8 R2 cannot resurrect that wall;
- handheld equip/health observations cannot reacquire trigger/lightbar ownership;
- handheld continuous and finite haptics stay suppressed;
- sustained handheld controller-speaker ownership is cleared and cannot restart;
- `LoadingMenu` close cannot release suppression while vehicle context remains;
- vehicle exit restores no stale state;
- fresh post-exit on-foot observations rebuild normal behavior.

The original v0.3.80 diagnostic regression is retained but updated to allow exactly
the two suppression-only lifecycle `GameEventType` additions. It still rejects any
land-vehicle haptic/trigger/speaker production API.

## Local verification boundary

The reconstructed Linux tree does not contain every unchanged historical core
source required to compile the new integrated consumer test. Portable v0.3.80
recon tests are run under GCC and Clang with warnings-as-errors, and the source
contracts are run locally. The supplied Windows gate is authoritative for the new
integrated C++ test, retained ship/controller suites, CommonLibSF DLL build,
installation, and VERSIONINFO verification.

Expected DLL version remains `0.3.80.0` and runtime marker remains
`0.3.80-land-vehicle-state-recon`.
