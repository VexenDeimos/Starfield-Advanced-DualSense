## Scope

v0.3.66 is a diagnostic-only reconnaissance build for ship particle weapons. The accepted ship families remain frozen:

- ballistic: v0.3.63-r6 exact `0x490502BD` hardware-alias/semantic path, including first-shot forward correlation and same-object native automatic heartbeat;
- pulse laser: v0.3.65-r2 exact `0xCE7B2EB1` authority, 250 ms lease, smooth adaptive-trigger resistance, 0.55 continuous overlay, and 0.55 / 40 ms pulse crest.

No particle output is promoted in this build. Particle Wwise traffic is observed only to learn the real native lifecycle.

The historical `ShipLaserReconProbe` implementation is reused unchanged because it is family-agnostic. Runtime particle recon keeps its proven boundaries:

- pilot authority required;
- physical R2 threshold `24`;
- 180 ms pre-press Wwise lookback;
- 250 ms post-release observation tail;
- exact event ID, Wwise game object, Starfield callsite, returned playing ID, trigger-relative phase, and native interval summaries;
- DataMenu/PauseMenu, loading invalidation, pilot exit, and shutdown clear the probe.

Particle-recon lines add:

- `knownBallistic=yes/no` for accepted ballistic evidence;
- `knownLaser=yes/no` for exact accepted pulse-laser event `0xCE7B2EB1`.

Those tags are exclusion evidence, not particle classification.

## Focused hardware test

Use one **particle weapon group only on W0/R2**. Do not fire the other ship weapon groups during the focused capture.

1. Enter pilot context and let normal propulsion settle for a couple of seconds.
2. Tap R2 once, then wait about 2 seconds.
3. Tap R2 a second time, then wait about 2 seconds.
4. Hold R2 for 2-3 seconds, release, and wait about 1 second.
5. Hold R2 again for 2-3 seconds, then release.
6. Open DataMenu while still piloting, wait briefly, then close it.
7. Fire one final 1-2 second particle burst.
8. Stop firing and leave enough time for the 250 ms post-release summary to flush.

Because this build is recon-only, **do not expect particle-specific trigger resistance or particle-specific vibration**. The generic cockpit/propulsion presentation may still be present. If pulse-laser or ballistic feedback appears during the isolated particle test, note it; the log tags will tell us whether an already-known family event was present.

## Interpretation rules

Do not promote an event merely because it appears during R2 hold. A strong particle candidate should repeat across multiple isolated bursts with stable event identity and a coherent relationship to R2 timing. One-off HUD/UI/mechanical events remain untrusted.

Possible outcomes:

- **Repeated same-event/same-object heartbeat:** candidate for pulse-like native particle cadence.
- **Distinct start + stop events:** candidate for a sustained particle texture with explicit lifecycle.
- **One event per pull only:** candidate for a discrete particle impulse.
- **Mixed or unstable events:** continue reconnaissance; do not guess.

No particle family should be promoted until the hardware evidence is repeatable.
