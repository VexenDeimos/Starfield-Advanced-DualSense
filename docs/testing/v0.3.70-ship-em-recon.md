## Scope

v0.3.70 is a diagnostic-only reconnaissance build for ship EM/Suppressor weapons. All four hardware-accepted ship-weapon families remain frozen:

- ballistic: v0.3.63-r6 exact `0x490502BD` hardware-alias/semantic path, including first-shot forward correlation and same-object native automatic heartbeat;
- pulse laser: v0.3.65-r2 exact `0xCE7B2EB1` authority, 250 ms lease, smooth adaptive-trigger resistance, 0.55 continuous overlay, and 0.55 / 40 ms pulse crest;
- Proton Beam particle: v0.3.67 exact `0xC8BBBCEA` authority, same-object native heartbeat, 60 ms / 0.70 discrete particle pulse, and 60 ms finite R2 energy break;
- missile: v0.3.69 exact `0x6846C9EC` authority, same-object native launch heartbeat, 105 ms / 0.90 launch thump, and 105 ms heavy finite R2 break.

No EM output is promoted in this build. EM Wwise traffic is observed only to learn the native firing lifecycle before any electrical haptic or adaptive-trigger feel is authored.

The historical `ShipLaserReconProbe` implementation is reused unchanged because it is family-agnostic. Runtime EM recon keeps the same proven boundaries:

- pilot authority required;
- physical R2 threshold `24`;
- 180 ms pre-press Wwise lookback;
- 250 ms post-release observation tail;
- exact event ID, Wwise game object, Starfield callsite, returned playing ID, trigger-relative phase, and native interval summaries;
- DataMenu/PauseMenu, loading invalidation, pilot exit, and shutdown clear the probe.

EM-recon lines add four exclusion labels:

- `knownBallistic=yes/no`;
- `knownLaser=yes/no`;
- `knownParticle=yes/no`;
- `knownMissile=yes/no`.

Those tags identify already-promoted families only. They do not classify an unknown event as EM.

## Focused hardware test

Use one **EM/Suppressor weapon group only on W0/R2**. Avoid firing ballistic, laser, particle, or missile groups during the focused capture.

1. Enter pilot context and let propulsion settle for about 2 seconds.
2. Tap R2 once; wait about 2 seconds.
3. Tap R2 again; wait about 2 seconds.
4. Hold R2 for 2-3 seconds; release and wait about 1 second.
5. Hold R2 again for 2-3 seconds; release.
6. Open DataMenu, wait briefly, then close it.
7. Fire one final 1-2 second EM burst.
8. Release R2 and wait at least 1 second so the 250 ms post-release summary can flush.

Because this build is reconnaissance-only, **do not expect any new EM-specific vibration or adaptive-trigger firing effect**. Normal cockpit/propulsion feedback remains expected.

## Interpretation rules

Do not promote an event merely because it appears during R2 hold. A strong EM candidate must repeat across isolated bursts with stable event/object identity and coherent timing relative to actual shots.

Possible outcomes:

- **One exact event per shot:** candidate for a discrete electrical pulse and finite light trigger break.
- **Repeated same-event/same-object heartbeat:** candidate for native EM cadence without a synthetic timer.
- **Start/stop lifecycle or sustained event:** candidate for a leased electrical buzz only if fresh native evidence continuously refreshes it.
- **Mixed or unstable events:** continue reconnaissance; do not guess.

No EM family output is promoted until hardware evidence is repeatable.
