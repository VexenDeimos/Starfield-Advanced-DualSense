# v0.3.55 UI Candidate Resolution + HUD Follow-up — Windows / Hardware Gate

v0.3.55 is diagnostic-only. It does **not** add UI/HUD controller-speaker playback. It corrects two real menu names discovered in the v0.3.54 hardware log, resolves eight evidence-selected Wwise event IDs to WEM files for listening, and adds a clean 60-second HUD-only follow-up after the existing 120-second menu session.

## Expected invariants

- One existing Wwise `PostEvent` hook only; no second interception path.
- Primary UI discovery remains 120 seconds, with the existing 150 ms menu-transition correlation window, 1024-record deferred queue, 512 aggregate cap, and 128 retained menu-transition cap.
- `GalaxyStarMapMenu` classifies as Map.
- `BSMissionMenu` classifies as Missions.
- HUD follow-up is exactly 60 seconds and starts only when no qualifying Inventory/Data/Pause/Map/Skills/Missions context is active.
- While waiting for clean HUD, Wwise UI capture is disarmed. During HUD follow-up, Wwise posts that occur while a qualifying menu is open are ignored.
- Eight fixed event IDs from the v0.3.54 hardware evidence are resolved on the existing background Wwise resolver and their referenced WEMs are written only under `Data/SFSE/Plugins/StarfieldDualSenseDiagnostics/v0.3.55/UiWemCandidates/`.
- No UI/HUD WEM is submitted to the controller speaker in this build.
- Weapon audio, VO, haptics, adaptive triggers, lightbar, touchpad, HID arbitration, USB speaker mapping, TESHit behavior, and normal Starfield audio remain unchanged.

## Runtime candidate-resolution check

Before launching, it is okay to delete the prior v0.3.55 candidate folder if this is a repeat run:

```text
Data\SFSE\Plugins\StarfieldDualSenseDiagnostics\v0.3.55\UiWemCandidates
```

After loading a save, allow the normal weapon-audio startup resolver to finish. The log should contain exactly one `UI Wwise candidate resolver:` line for each of these eight evidence-selected IDs:

```text
0x05234A32
0xF488F841
0x7470A961
0xC7F9CACC
0x0976086C
0xB32B4C8E
0x7956E9B0
0x5C8034FC
```

Resolved candidates may produce one or more `UI Wwise candidate media:` lines. Any successfully found WEM should appear below the v0.3.55 `UiWemCandidates` folder and in its `manifest.tsv`. A `not-found` result is useful evidence and is not a runtime failure.

## In-game discovery sequence

1. Load fully into gameplay and wait for startup activity to settle.
2. Open **Inventory** (or another qualifying menu) to start the 120-second primary session.
3. Exercise Inventory navigation/select/back actions.
4. Open the **Galaxy Star Map**, move/select/back several times.
5. Open **Skills**, navigate several skills and open/close details.
6. Open **Missions**, navigate missions and optionally change the active mission.
7. Use the **Data/Pause** interface and several confirm/back actions.
8. Continue until at least 120 seconds have elapsed from the first qualifying-menu open.
9. **Close every full-screen qualifying menu.** If one was still open at the 120-second boundary, the log should show the primary completion first and then begin the HUD follow-up only after the last qualifying menu closes.
10. Once `UI audio HUD follow-up: START` appears, remain in normal gameplay for 60 seconds. Do not intentionally open Inventory/Data/Pause/Map/Skills/Missions during this minute.
11. During the HUD minute, trigger ordinary HUD activity where convenient: item pickup/loot text, objective/mission update, scanner enter/exit, interaction/status notifications, or other normal HUD popups.
12. Wait for `UI audio HUD follow-up: COMPLETE`, then quit Starfield normally.

The HUD summary should report its own `rawEvents`, `uniqueCandidates`, and `dropped` counts. A normal run should have `dropped=0`.

## Return artifacts

Send back:

1. The fresh `StarfieldDualSense(...).log`.
2. A ZIP of:

```text
Data\SFSE\Plugins\StarfieldDualSenseDiagnostics\v0.3.55\UiWemCandidates
```

The WEMs plus `manifest.tsv` let us identify which candidates are navigation, confirm/back, menu-open/close, mission/map/skills-specific, or unsuitable background/layer events before any controller-speaker playback is designed.
