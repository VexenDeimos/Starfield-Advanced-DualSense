# v0.3.59 Expanded Menu Promotion + Full-Session UI Discovery — Windows / Hardware Gate

## Scope

This release adds exactly five production UI controller-speaker events to the five already accepted in v0.3.57. The scanner open/close pair is frozen. `UIItemFocus` remains excluded. The diagnostic window now follows the Data Menu session, capped at five minutes, and resolves the 33 still-unknown v0.3.58 primary-menu event IDs in memory without WEM extraction.

## Windows build gate

Expected installed DLL versions:

- ProductVersion: `0.3.59.0`
- FileVersion: `0.3.59.0`

Run the focused v0.3.59 targets first, then the retained v0.3.54–v0.3.58 UI tests and source regressions, then build the plugin.

## Hardware run

Use:

- `DebugLogging = true`
- `ControllerSpeaker = true`
- `SpeakerScannerUI = true`

After loading a save:

1. Verify the existing GeneralFocus / OK / Cancel sounds still behave normally.
2. Open and close the scanner and verify its two accepted sounds are unchanged.
3. Enter Skills and move repeatedly across skills; listen for the promoted Skills focus sound.
4. Enter Galaxy Star Map and Surface Map; move across map targets repeatedly.
5. Enter Missions; move through mission entries and toggle subtasks repeatedly.
6. Continue through Inventory, ship editor / crew, Container, Powers / Favorites, Almanac, Status, and any other Data Menu submenus for as much of the session as practical.
7. Keep DataMenu open for longer than two minutes at least once. The primary discovery must remain active beyond the old 120-second boundary.
8. Close DataMenu. This should end primary discovery and start the existing clean-HUD follow-up when only HUD context remains.
9. Leave menus closed and play normally for at least 60 seconds so the HUD follow-up completes.
10. Quit Starfield normally and retain the complete `StarfieldDualSense(...).log`.

## Expected log evidence

Startup should report:

- `StarfieldDualSense 0.3.59-expanded-menu-promotion-full-session-discovery`
- `UI/scanner speaker: ACTIVE cues=10`
- `UI audio discovery: ACTIVE ... end=DataMenu-close maxDurationMs=300000 ... existingPromotedPlayback=10`
- `targetedResolution=33`
- `UI diagnostic resolution:` / `UI diagnostic media:` lines with `extraction=disabled`
- ten `UI speaker cue ready:` lines if all promoted cues resolve successfully

Primary completion should report its actual duration rather than always `120000`. If DataMenu is closed at roughly three minutes, for example, the summary should be near `durationMs=180000`. If DataMenu never closes, the hard cap should complete at `durationMs=300000`.

The HUD follow-up remains exactly 60 seconds. Normal Starfield audio must remain present throughout.
