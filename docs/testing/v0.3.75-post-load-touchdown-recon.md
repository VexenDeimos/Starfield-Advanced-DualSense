# StarfieldDualSense v0.3.75 Post-Load Touchdown Recon

## Purpose

v0.3.75 remains diagnostic-only. It keeps the accepted v0.3.74 landing-sequence Wwise capture, then adds a fresh post-load ship-state read while normal pilot/menu authority is unavailable. The diagnostic read resolves the current player, current ship, and current pilot on every poll; it does not retain a ship pointer across loading.

If the landing candidate observes `landed=false -> landed=true`, the probe records `touchdownObservedDeltaUs` relative to the original landing-sequence anchor and keeps Wwise capture alive for another two seconds. The report then finalizes without requiring `TakeoffMenu` to close or a second Fader/Loading cycle.

The diagnostic state path never feeds propulsion haptics, weapon haptics, adaptive triggers, lightbar, or controller-speaker output. Docked state cancels the landing candidate.

ProductVersion/FileVersion: `0.3.75.0`
Runtime marker: `0.3.75-post-load-touchdown-recon`

## Windows gate

Run the supplied `StarfieldDualSense_v0.3.75_Post_Load_Touchdown_Recon_Windows_Gate.ps1` from PowerShell after applying the changed-files ZIP.

Expected final lines:

```text
V0.3.75 POST-LOAD TOUCHDOWN RECON WINDOWS BUILD/INSTALL GATE PASSED.
Expected ProductVersion: 0.3.75.0
Expected FileVersion:    0.3.75.0
Expected runtime marker: 0.3.75-post-load-touchdown-recon
```

## Hardware run

1. It is fine to start from an on-foot save.
2. Enter the ship and take off until the ship is in normal spaceflight with pilot authority.
3. Fly for several seconds.
4. Open the starmap and choose a planet/moon landing site that plays the full third-person landing sequence.
5. Land normally and do not skip or interrupt the sequence.
6. When the sequence completes, remain seated in the pilot chair. Do not exit the ship just for the test.
7. Wait at least 10 seconds after the landing sequence finishes.
8. Quit Starfield normally and provide the newest `StarfieldDualSense(...).log`.

## Expected diagnostic evidence

During the landing load, normal pilot authority should still invalidate as before. While the landing candidate remains active, v0.3.75 may emit fresh diagnostic lines such as:

```text
Ship landing recon state: ... pilotConfirmed=yes landed=no ... diagnostic-only
Ship landing recon state: ... pilotConfirmed=yes landed=yes ... diagnostic-only
Ship launch/landing recon: boundary=touchdown ... beforeLanded=no afterLanded=yes ... diagnostic-only
```

A successful landing-sequence report should contain:

```text
boundary=landing-sequence
stateBoundaryObserved=yes
afterLanded=yes
touchdownObservedDeltaUs=<value>
```

and should retain Wwise samples from both before and after the observed touchdown time.

If the diagnostic state never becomes available or never reaches `landed=yes`, do not retry repeatedly. Send the log as-is; that is useful recon evidence too.
