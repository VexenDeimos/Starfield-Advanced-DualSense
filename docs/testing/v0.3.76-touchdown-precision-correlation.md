# StarfieldDualSense v0.3.76 Touchdown Precision Correlation

## Purpose

v0.3.76 is a diagnostic-only refinement of the accepted v0.3.75 post-load touchdown recon. Two independent hardware landings placed native Wwise event `0x456ED309` within the coarse 200 ms landed-state polling window around the real `landed=false -> landed=true` transition, but the existing cadence is too slow to establish event ordering.

This build leaves the accepted ship haptics, triggers, speaker behavior, propulsion, takeoff recon, weapon families, and docking suppression unchanged. After a valid landing candidate completes its first Fader/load phase and the first Fader closes, the probe requests a fresh landed-state read on each SFSE runtime tick until touchdown is observed or the candidate is cancelled. The precision read resolves player -> current ship -> current pilot every call and never reuses a ship pointer across loading.

## Hardware procedure

1. Load a save. Starting on foot is fine.
2. Enter the pilot chair, take off, and establish normal flight in space.
3. Use the starmap to choose a landing site that plays the full third-person landing sequence.
4. Let the landing sequence play naturally. Do not skip it or open unrelated menus.
5. Remain seated in the pilot chair after the cinematic ends.
6. Wait about 5 seconds after the ship is visibly landed.
7. Quit Starfield normally and send the full newest `StarfieldDualSense(...).log`.

## Evidence to inspect

During the final cinematic tail, the log should contain repeated fresh diagnostic lines like:

```text
Ship landing precision state: ... landed=no ... cadence=runtime-tick diagnostic-only
```

followed by the first fresh `landed=yes` observation and the existing diagnostic touchdown boundary. The final landing report should still contain `stateBoundaryObserved=yes`, `afterLanded=yes`, and `touchdownObservedDeltaUs=...`.

Compare `touchdownObservedDeltaUs` directly with the Wwise report deltas for the cluster around `0xA37F9888`, the `0x591EE9FF` burst, `0x456ED309`, `TakeoffMenu`, `0x72FDF073`, and `0xB0E838AE`. Do not promote any event from this build alone; the goal is to determine ordering at runtime-tick resolution.

## Safety / scope

- Diagnostic-only touchdown precision polling.
- No controller output is added by landing recon.
- Precision polling starts only after the first landing Fader closes and ends immediately on touchdown/cancellation.
- Normal 200 ms ship propulsion polling remains unchanged for production haptics.
- Docking remains suppressed as a landing candidate.
- No Wwise ID gains a semantic name or haptic authority in v0.3.76.
