# v0.3.50 Starstorm Speaker Diagnostic

## Scope

This build is diagnostic-only. It does not change Starstorm audio gain, routing, loop points, start/stop behavior, haptics, triggers, or normal Starfield audio. It measures media `963157375` at preparation time and at bounded runtime render checkpoints.

The startup log emits `Starstorm PCM diagnostic:` windows with left/right/mono peak and RMS levels plus left/right correlation. During a Starstorm sustained hold, the runtime emits `Starstorm render diagnostic:` checkpoints at approximately 0, 0.5, 2.5, 3.0, and 5.0 seconds of rendered persistent audio. The 3-second checkpoint is intentionally after the 120,000-frame sustained-start transient window.

## Hardware diagnostic

Keep `DebugLogging=true`. Test only the Va'ruun Starstorm. Fire at least two sustained holds of 6 seconds or longer with a full R2 release between them, then quit normally and return the fresh `StarfieldDualSense` log.

The log should contain:

- startup `Starstorm PCM diagnostic:` lines for the complete prepared body and bounded time windows;
- `stage=persistent-applied` when media `963157375` is accepted;
- `stage=output-block` checkpoints through at least `checkpointFrames=240000` (5 seconds), reporting logical L/R/mono levels plus final `peakCh2` and `rmsCh2`;
- `stage=persistent-cleared` at the real Wwise stop.

Interpretation is intentionally deferred until the hardware log is returned. In particular, this build does not assume phase cancellation is the root cause.
