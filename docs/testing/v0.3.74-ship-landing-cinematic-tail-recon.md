# v0.3.74 Ship Landing Cinematic-Tail Reconnaissance

## Purpose

v0.3.74 is diagnostic-only. It extends the v0.3.73 landing-sequence reconnaissance window across the observed cinematic tail after the first landing load. It does not add landing/takeoff controller output and does not change propulsion or ship-weapon haptics.

The full-cinematic candidate now follows:

1. authoritative airborne ship state (`landed=no`, `docked=no`)
2. planetary landing/travel initiation
3. first `FaderMenu` / `LoadingMenu` phase
4. `SpaceshipHudMenu` closes during the first load
5. first `LoadingMenu` closes
6. first `FaderMenu` closes
7. bounded cinematic-tail wait (15 seconds maximum while waiting for `TakeoffMenu`)
8. `TakeoffMenu` opens and closes
9. second `FaderMenu` / `LoadingMenu` phase
10. second `LoadingMenu` closes
11. second `FaderMenu` closes
12. one combined diagnostic report is emitted

If `TakeoffMenu` never appears during the 15-second tail wait, the probe falls back to the original first-phase landing report and discards Wwise samples captured after the first `FaderMenu` close.

The whole landing candidate remains globally bounded to 30 seconds from its first Fader/Loading anchor.

## Hardware test — full landing cinematic

1. Start Starfield with a wired DualSense and v0.3.74 installed.
2. Load a save and get into the ship in space.
3. Fly normally for several seconds so the probe receives a clean airborne state.
4. Open the starmap and select a planet/moon landing site that plays the visible third-person landing cinematic. Avoid New Atlantis for this pass.
5. Select **Land** normally.
6. Do not pause or interrupt the landing, cinematic, or loading screens.
7. Once normal surface gameplay is fully restored, wait about 10 seconds.
8. Quit Starfield normally.
9. Send the newest `StarfieldDualSense(YYYYMMDD-HHMMSS).log`.

## What the log should contain

Startup should include:

- `StarfieldDualSense 0.3.74-ship-landing-cinematic-tail-recon runtime start`
- `cinematicTailWaitMs=15000`
- `controllerOutput=none`

A successful full-cinematic capture should emit exactly one `boundary=landing-sequence` report whose summary includes:

- `faderClosedDeltaUs=` for the first Fader close
- `takeoffMenuOpenedDeltaUs=`
- `takeoffMenuClosedDeltaUs=`
- `secondFaderOpenedDeltaUs=`
- `secondLoadingOpenedDeltaUs=`
- `secondLoadingClosedDeltaUs=`
- `secondFaderClosedDeltaUs=`
- `cinematicTail=observed`

Per-Wwise lines include the menu snapshot:

`menus=map:...,fader:...,loading:...,hud:...,takeoff:...`

## Optional fallback check

A location that skips the visible landing cinematic (for example the previously observed New Atlantis flow) is useful later to verify the bounded fallback path. The expected summary there is `cinematicTail=fallback`, with the second-phase timings reported as `na`.
