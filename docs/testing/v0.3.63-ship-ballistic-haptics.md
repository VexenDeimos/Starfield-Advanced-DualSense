## Hardware evidence behind r6

r5 passed the sustained automatic-fire behavior and DataMenu suppression on hardware, but a short R2 tap produced no cannon kick. The log showed the ordering race directly:

- first burst: `0x490502BD` candidate at about `10:24:25.678`; the next heartbeat at `10:24:25.890` finally had R2 correlation and kicked;
- second burst: first candidate at about `10:24:32.853`; the next heartbeat at `10:24:33.066` finally had R2 correlation and kicked.

Using the correlated second-heartbeat `deltaUs` values, the first qualifying R2 sample landed roughly **144-157 ms after the first Wwise heartbeat**. The weapon itself reposted the real heartbeat roughly every **208-223 ms**. r5 therefore did not have a waveform problem: its first-shot gate was looking only backward for R2 evidence while the real first Wwise event was arriving first.

## r6 scope

r6 preserves the hardware-accepted r2 cockpit R2 wall, propulsion haptics, Data/Pause mute, loading lifecycle, r4 `0x490502BD` promotion, and r5 same-object automatic heartbeat.

The only behavior change is one bounded first-shot forward-correlation slot:

- only exact hardware alias `0x490502BD` may stage it;
- the event remains inert until a real physical R2 sample reaches the existing threshold;
- the R2 proof must arrive within **180 ms**;
- the earliest still-live Wwise game object is retained, so another object cannot replace it;
- once proven, exactly one `ShipBallisticWeaponFired` semantic is emitted and r5's same-object automatic stream is armed;
- the finite effect uses the R2 proof time for delivery so the 45 ms kick is not already expired;
- physical R2 release, DataMenu/PauseMenu transitions, loading/pilot invalidation, pilot exit, and shutdown clear pending authority.

The 180 ms window is intentionally shorter than the observed 208-223 ms native automatic heartbeat. There is **no synthetic cadence, guessed RPM, delayed timer shot, or raw-R2-only recoil**. Subsequent automatic kicks still require actual Starfield `0x490502BD` posts from the same Wwise object while R2 remains held. Catalog-only ballistic IDs and laser/particle/missile/EM ship families do not gain this forward path.

## Focused hardware run

Use the same automatic R2-controlled ballistic ship weapon from the r5 run.

1. Enter the pilot seat and confirm the normal cockpit R2 wall and propulsion texture.
2. **Tap R2 once.** You should now feel exactly one finite cannon kick. A short first-shot delay is acceptable for this gate; zero kicks or two kicks is not.
3. Wait about two seconds, then hold R2 for 2-3 seconds. The first shot should kick and the burst should continue with repeated rhythmic kicks following the weapon's real native cadence.
4. Release R2. Kicking must stop immediately with no run-on.
5. Hold R2 again. Repeated kicks must reacquire normally.
6. Open DataMenu during flight. Ship vibration and ship trigger output must mute immediately.
7. Close the menu, fire again, then quit normally and send the fresh log with how the single tap and sustained burst feel.
