# v0.3.36 Batch 1 One-Pass Weapon Audio Discovery - Startup Fix

v0.3.36 is the startup-regression fix for the Batch 1 diagnostic. The existing 11 live weapon-speaker profiles remain unchanged. The 15 Batch 1 weapons should **not** produce new controller-speaker weapon sounds yet; this run collects the exact same-session Wwise event/media evidence used to build the next profile batch.

Unlike v0.3.35, startup does **not** enumerate SoundBanksInfo by weapon-name substring. The reusable Wwise catalog is prepared once, then exact Wwise event IDs observed while you actually use a weapon are resolved live. This prevents short names such as `Eon` from accidentally matching unrelated media such as `Dungeon` and avoids the pathological startup workload seen in v0.3.36.

Keep `DebugLogging = true`, `ControllerSpeaker = true`, and `SpeakerWeapons = true` for this discovery run.

```text
equip -> draw -> wait ~1 s -> fire 3-5 single shots or ~1 s automatic burst -> reload -> wait ~1 s -> holster -> wait ~1 s
```

Do not restart Starfield between weapons. Use the default/unmodified spawned receiver configuration for this discovery pass.

Expected behavior:

- The current 11 known profiles continue to work if used.
- These 15 Batch 1 weapons do **not** yet gain new controller-speaker weapon sounds in v0.3.36.
- Normal Starfield audio remains unchanged.
- Each Batch 1 weapon should generate `Weapon SFX resolved event:` and `Weapon SFX resolved media:` lines during this same session.

After all 15 are complete, exit Starfield normally and send the single `StarfieldDualSense(...).log` file.
