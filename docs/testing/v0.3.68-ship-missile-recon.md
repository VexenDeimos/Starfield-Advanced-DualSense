## Scope

v0.3.68 is a diagnostic-only reconnaissance build for ship missile launchers. The accepted ship families remain frozen:

- ballistic: v0.3.63-r6 exact `0x490502BD` hardware-alias/semantic path, including first-shot forward correlation and same-object native automatic heartbeat;
- pulse laser: v0.3.65-r2 exact `0xCE7B2EB1` authority, 250 ms lease, smooth adaptive-trigger resistance, 0.55 continuous overlay, and 0.55 / 40 ms pulse crest;
- Proton Beam particle: v0.3.67 exact `0xC8BBBCEA` authority, same-object native heartbeat, 60 ms / 0.70 discrete particle pulse, and 60 ms finite R2 energy break.

No missile output is promoted in this build. Missile Wwise traffic is observed only to learn the real native launch lifecycle.

The historical `ShipLaserReconProbe` implementation is reused unchanged because it is family-agnostic. Runtime missile recon keeps its proven boundaries:

- pilot authority required;
- physical R2 threshold `24`;
- 180 ms pre-press Wwise lookback;
- 250 ms post-release observation tail;
- exact event ID, Wwise game object, Starfield callsite, returned playing ID, trigger-relative phase, and native interval summaries;
- DataMenu/PauseMenu, loading invalidation, pilot exit, and shutdown clear the probe.

Missile-recon lines add three exclusion labels:

- `knownBallistic=yes/no` for accepted ballistic evidence;
- `knownLaser=yes/no` for exact accepted pulse-laser event `0xCE7B2EB1`;
- `knownParticle=yes/no` for exact accepted Proton Beam event `0xC8BBBCEA`.

Those tags are exclusion evidence, not missile classification.

## Focused hardware test

Use one **missile launcher group only on W0/R2**. Do not fire the other ship weapon groups during the focused capture.

1. Enter pilot context and let normal propulsion settle for a couple of seconds.
2. Tap R2 once, then wait about 2 seconds.
3. Tap R2 a second time, then wait about 2 seconds.
4. Hold R2 for 2-3 seconds, release, and wait about 1 second.
5. Hold R2 again for 2-3 seconds, then release.
6. Open DataMenu while still piloting, wait briefly, then close it.
7. Fire one final 1-2 second missile burst.
8. Stop firing and leave enough time for the 250 ms post-release summary to flush.

Because this build is recon-only, **do not expect missile-specific trigger resistance or missile-specific vibration**. The generic cockpit/propulsion presentation and the already-accepted families remain available, but the isolated test should avoid firing them.

## Interpretation rules

Do not promote an event merely because it appears during R2 hold. Missile launchers may also emit lock, seeker, motor, reload, UI, or impact-related audio. A strong launch candidate should repeat across multiple isolated bursts with stable identity and a coherent relationship to actual launch timing.

Possible outcomes:

- **One exact event per actual missile launch:** candidate for a discrete heavy launch thump and finite trigger break.
- **Repeated same-event/same-object heartbeat:** candidate for launcher-native cadence, still without a synthetic timer.
- **Distinct start + release/stop companions:** investigate whether the weapon has a charging/lock/launch lifecycle before promotion.
- **Mixed or unstable events:** continue reconnaissance; do not guess.

No missile family should be promoted until the hardware evidence is repeatable.
