# v0.3.40 Auto-Rivet Gameplay Gating

## Purpose

This is a focused haptics correction for Auto-Rivet. The accepted v0.3.39 Batch 2 controller-speaker mappings are intentionally unchanged.

The v0.3.39 runtime log showed `DataMenu` / `PauseMenu` activity but no delivered `GamePaused` event. In this CommonLibSF build the app-pause event-source relocation is unavailable, so v0.3.40 uses the live menu stream for Auto-Rivet safety. Raw R2 is also no longer enough to create Auto-Rivet tension: the continuous layer requires a player-object Wwise charge-start semantic before trigger depth can drive it.

Expected speaker catalog remains:

- logical profiles: 36
- physical audio families: 35
- cues: 221
- unique physical variants: 321
- discovery targets: 0

## Hardware acceptance

Use Auto-Rivet for the focused test. The normal pre-fire feel is still a lighter mechanical vibration that builds with trigger depth, followed by the much stronger discharge hit.

1. Equip Auto-Rivet and pull R2 normally. Confirm the held tension begins during a real accepted charge and release/fire still gives the stronger discharge.
2. While held tension is active, open the Data/Pause menu. Tension must stop immediately. Keep R2 physically held while closing the menu: vibration must **not** resume just because the trigger is still held. Release it, then make a fresh normal pull; tension should work again.
3. Reload Auto-Rivet. At several points during the reload, press/hold R2. There must be **no** Auto-Rivet tension while the weapon cannot accept a charge. After reload completes, the next genuine trigger pull should authorize tension normally.
4. Exercise a loading screen with Auto-Rivet selected. Held tension must not continue through `LoadingMenu`.
5. Sanity-check one or two Batch 2 controller-speaker weapons. Their fire/reload/draw/holster audio should be unchanged from v0.3.39.

The log should include this startup marker when advanced haptics are enabled:

```text
Auto-Rivet tension gate: rawR2=no-authority chargeSource=player-Wwise blockingMenus=DataMenu,PauseMenu,LoadingMenu resumeRequiresFreshChargeStart=yes
```

On a normal Auto-Rivet charge/fire cycle, look for:

```text
Auto-Rivet tension: charge-start semantic observed source=player-Wwise
Auto-Rivet tension: charge-stop semantic observed source=player-Wwise
```

The `Charge_Stop` event was observed directly in the discovery run. The paired `Charge_Start` ShortID is deterministic but still needs this hardware run to prove Starfield posts it on the player object. If the start diagnostic never appears, pre-fire tension will intentionally stay silent rather than falling back to unsafe raw-R2 authorization; retain the log for the next evidence-based adjustment.
