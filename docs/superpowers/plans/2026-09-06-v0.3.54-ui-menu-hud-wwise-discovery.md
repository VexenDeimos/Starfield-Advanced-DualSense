# v0.3.54 UI/Menu + HUD Wwise Discovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one bounded, diagnostic-only 120-second UI/menu + HUD Wwise discovery session that correlates zero-external `PostEvent` observations with Starfield menu state without changing any controller, speaker, haptic, trigger, VO, weapon, or normal game-audio behavior.

**Architecture:** A new portable core `UiAudioDiscoveryProbe` owns session lifecycle, menu-context mapping, correlation, bounded aggregation, drop accounting, and deterministic log formatting. `StarfieldAudioCapture` reuses its existing `PostEvent` thunk and adds a separate fixed-capacity UI observation queue/callback beside the existing weapon queue; `Plugin.cpp` forwards normalized menu `GameEvent`s to the probe, arms capture only while the probe is active, drains diagnostics on the normal runtime tick, and flushes the aggregate summary on timeout or shutdown.

**Tech Stack:** C++23, xmake, CommonLibSF/SFSE, existing Wwise `AkSoundEngine::PostEvent` interception, fixed-capacity lock-free deferred capture queue, Python source-regression tests.

**Spec:** `docs/superpowers/specs/2026-09-06-ui-menu-hud-wwise-discovery-design.md`

## Global Constraints

- Baseline is exactly StarfieldDualSense `v0.3.53`.
- Target implementation version is exactly `0.3.54`; installed `ProductVersion` and `FileVersion` must be `0.3.54.0`.
- Runtime marker is exactly `0.3.54-ui-menu-hud-wwise-discovery`.
- The discovery session is one-shot per process and lasts exactly `120000 ms` from the first qualifying menu-open event.
- `HUDMenu`, loading/fader menus, dialogue-only menus, and startup-only transient menus never independently start the session.
- The UI path observes only zero-external-source Wwise `PostEvent` calls while its session is active.
- Reuse the existing `StarfieldAudioCapture` `PostEvent` hook; do not install a second Wwise hook.
- The intercepted original `PostEvent` call and returned playing ID remain authoritative and unchanged.
- The Wwise interception path never waits, performs no unbounded allocation, and drops UI diagnostic records rather than blocking.
- Runtime UI discovery does not replay, stop, replace, decode, mirror, extract, or route UI/HUD audio.
- No UI/HUD sound is submitted to `ControllerSpeakerManager`, `SpeakerMixer`, `DualSenseAudioTransport`, or any haptic/trigger path in v0.3.54.
- Existing weapon speaker audio, weapon discovery, remote VO, haptics, adaptive triggers, lightbar, touchpad, HID arbitration, USB speaker mapping, and normal Starfield audio behavior remain unchanged.
- UI discovery is enabled only when `DebugLogging=true`; no new user-facing config key is introduced for this one-purpose diagnostic build.
- Future UI/HUD playback promotion is out of scope for v0.3.54, but when implemented it must use the existing `SpeakerCategory::ScannerUI` / `SpeakerScannerUI` player-facing gate; `ControllerSpeaker` remains the master switch.
- The transition-correlation interval is exactly `150 ms` in either direction and is used only as a tag, never as a filter.
- Core aggregation is bounded to `512` distinct candidate aggregates and `128` retained menu transitions; overflow is surfaced in diagnostics.
- The StarfieldAudioCapture UI deferred queue capacity is exactly `1024` records.
- Final aggregate ordering is deterministic: context mask, event ID, game-object ID, then callsite RVA.
- User-facing source delivery remains changed/new files only, preserving repository-relative paths.

- [ ] **Step 6: Implement minimal session/context/correlation/aggregation logic**

Implementation rules in `src/core/UiAudioDiscoveryProbe.cpp`:

```cpp
// Session interval is [startedAt, deadline): an observation at deadline is out of window.
// Context counts are per UiAudioContext bit, not booleans, so aliases/overlap close safely.
// Unknown menu names increment/decrement Other; HUD names map to Hud but never trigger.
// Every relevant transition is retained in a 128-slot ring; overwriting the oldest increments transitionDrops.
// When a new transition is observed, rescan existing aggregates whose first/last interval could be within 150ms
// so a Wwise event that happened just before a menu transition can be upgraded to transitionCorrelated=true.
// Aggregate lookup is linear across a fixed std::array<UiAudioAggregate, 512>; no map/unbounded container.
// A 513th distinct key increments aggregateOverflowDrops and returns false.
```

Use `GameEvent::when` as the authoritative menu timestamp and `UiAudioWwiseObservation::when` as the authoritative Wwise timestamp. Calculate session-relative milliseconds with `duration_cast<milliseconds>(when - startedAt).count()`.

Queue these bounded diagnostic lines in core state (at most one START line, 128 transition lines, 512 first-seen lines, one COMPLETE line, and 512 final aggregate lines):

```text
UI audio discovery: START trigger=<exact menu> durationMs=120000
UI audio discovery menu: tMs=<n> action=open|close menu=<exact name> context=<logical context>
UI audio discovery candidate: event=0xXXXXXXXX gameObject=0x... callsite=Starfield+0x... context=<mask names> firstMs=<n> transitionCorrelated=yes|no
UI audio discovery: COMPLETE durationMs=<actual bounded elapsed> rawEvents=<n> uniqueCandidates=<n> menuCorrelated=<n> hudPeriodCandidates=<n> dropped=<queue+aggregate drops> transitionDrops=<n>
UI audio candidate: event=0xXXXXXXXX gameObject=0x... callsite=Starfield+0x... context=<mask names> count=<n> firstMs=<n> lastMs=<n> requestedPlayingId=<n> returnedPlayingId=<n> transitionCorrelated=yes|no
```
