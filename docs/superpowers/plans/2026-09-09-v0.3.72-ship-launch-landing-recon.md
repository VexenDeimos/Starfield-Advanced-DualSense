# v0.3.72 Ship Launch/Landing Recon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add diagnostic-only ship launch/landing reconnaissance that correlates reliable `landed` state boundaries with bounded pre/post Wwise activity, without producing any new controller output.

**Architecture:** Add a small portable `ShipLaunchLandingReconProbe` that consumes authoritative `ShipPropulsionState` snapshots plus zero-external Wwise observations. It keeps a 2-second rolling pre-transition buffer, detects only non-docked `landed=true→false` takeoff and `landed=false→true` touchdown boundaries, then collects 2 seconds of post-transition Wwise evidence into a bounded report. `Plugin.cpp` owns the probe, feeds it from the existing 200 ms ship-state poll and ship Wwise observation callback, logs transition/report diagnostics, and keeps all accepted ballistic/laser/particle/missile/EM output frozen.

**Tech Stack:** C++23, CommonLibSF/SFSE runtime integration, existing `StarfieldAudioCapture`, Python source regressions, portable GCC/Clang unit tests, xmake Windows build gate.

**Spec:** Approved conversation design: v0.3.72 diagnostic-only launch/landing recon before any launch/landing haptic authoring.

## Global Constraints

- Runtime marker is `0.3.72-ship-launch-landing-recon` and DLL/project version is `0.3.72.0` / `0.3.72`.
- Recon is diagnostic-only: no new `GameEventType`, haptic effect, adaptive-trigger effect, lightbar effect, speaker cue, or synthetic timing output.
- Detect takeoff only from a confirmed pilot-state `landed=true→false` transition where neither side is docked.
- Detect touchdown only from a confirmed pilot-state `landed=false→true` transition where neither side is docked.
- First state observation is an anchor only; it must never fabricate a transition.
- Retain 2000 ms of Wwise evidence before the boundary and 2000 ms after it; preserve exact event ID, gameObject, callsite, returned playing ID, sequence, and signed boundary-relative timing.
- Cap buffered/report Wwise samples to prevent unbounded diagnostic growth.
- DataMenu/PauseMenu, loading/pilot invalidation, pilot exit, and shutdown clear recon state; stale evidence must not survive reacquisition.
- Existing accepted ship weapon baselines remain frozen: ballistic r6, laser r2, particle v0.3.67, missile v0.3.69, EM v0.3.71-r2.
- Existing propulsion haptics remain untouched.
