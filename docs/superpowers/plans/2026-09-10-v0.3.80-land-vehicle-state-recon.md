# v0.3.80 Land Vehicle State Recon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a passive, diagnostic-only REV-8/land-vehicle reconnaissance path that proves driver lifecycle and vehicle identity candidates before any land-vehicle controller effects are added.

**Architecture:** Keep land vehicles in a dedicated portable recon domain. Observe the engine's `VehicleDriverEnterExitEvent` source as raw, bounded evidence; corroborate it with CommonLibSF's `PlayerCamera::kVehicle` state and loading/menu lifecycle; promote no raw event field to authoritative vehicle identity until a hardware log proves it. Once a stable candidate exists, poll only guarded, read-only telemetry from that candidate in later v0.3.80 revisions.

**Tech Stack:** C++23, CommonLibSF, SFSE, Windows guarded memory reads, xmake, Python source regressions.

**Spec:** `docs/superpowers/specs/2026-09-10-v0.3.80-land-vehicle-state-recon-design.md`

## Global Constraints

- Project version is `0.3.80`; Windows DLL ProductVersion/FileVersion must be `0.3.80.0`.
- Runtime marker is `0.3.80-land-vehicle-state-recon`.
- Supported Starfield runtime remains `1.16.244.0`.
- v0.3.80 is diagnostic-only: `controllerOutput=none` for land vehicles.
- No land-vehicle haptics, adaptive-trigger effects, controller-speaker cues, lightbar changes, native input changes, vehicle handling changes, or game-audio changes.
- Do not define vehicle ownership from raw controller input, `kVehicle` camera state, menu names, or a hard-coded REV-8 FormID.
- Raw driver-event bytes are evidence only until hardware correlation proves field semantics.
- Runtime reads must be guarded, passive, bounded, and fail closed.
- Accepted v0.3.79-r2 ship/on-foot/controller behavior remains frozen.
- Reuse existing Wwise capture infrastructure; do not create a second Wwise hook.
- Changed-file handoff contains only project files actually modified or created.

**Interfaces:**
- A raw qword lane becomes `driver` or `vehicle` only after at least one clean enter/exit session demonstrates stable, repeatable identity and safe form/reference validation.

Compare event payloads across on-foot, enter, idle, drive, loading, exit. Identify lanes that remain stable for the session and change/clear at the correct boundary.

Add a regression that locks the proven offset/layout and a runtime guard that validates the pointed object's identity before exposing it as Tier-A evidence.

- [ ] **Step 3: Add telemetry probes one group at a time**

Prioritize speed/velocity and drive/brake/boost. Suspension/contact/collision/slip remain separate recon revisions if the first log cannot prove them.
