# v0.3.89 Production Music Haptics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the first production Starfield score-driven DualSense haptics using exact Wwise-selected media authority.

**Architecture:** Preserve the v0.3.88 callback chain, lazily decode only selected score WEMs on the existing worker, and feed prepared PCM into an isolated music haptic mixer inside the shared DualSense audio transport. Gameplay haptics render first and side-chain duck the bounded music layer.

**Tech Stack:** C++23, CommonLibSF/SFSE, Wwise 2021.1 callback ABI, existing Wwise/BA2 resolver, WASAPI 4-channel DualSense audio transport, xmake/MSVC Windows gate, GCC/Clang portable gates.

**Spec:** `docs/superpowers/specs/2026-09-12-v0.3.89-production-music-haptics-design.md`

## Global Constraints
- Exact selected-media authority comes only from catalog-qualified `Starfield_MUS` callbacks.
- Preserve Starfield's callback cookie and callback forwarding semantics from v0.3.88.
- No filesystem/decoder/haptic rendering work on the Wwise callback thread.
- 350 ms music fade-in.
- Music layer peak cap 0.65.
- Stereo-ish 85/15 crossfeed.
- Existing gameplay haptics retain priority through side-chain ducking.
- Blocking boundaries: MainMenu, DataMenu, PauseMenu, LoadingMenu, FaderMenu, Shutdown.
- `MusicHapticsEnabled=true` by default; production music output additionally requires `AdvancedHaptics=true`.
- No whole-game capture, FFT, beat detector, or all-score predecode.
