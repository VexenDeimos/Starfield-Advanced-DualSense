# v0.2.47 Cutter Continuous Haptics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add confirmed-start, R2-shaped continuous controller-body haptics for the Starfield Cutter while preserving all frozen trigger, HID, fire-marker, and previous haptic behavior.

**Architecture:** Reuse the existing FireMarkerBridge-normalized `WeaponFired` event and exact `weaponFireStart` marker as the sole start authority. `HapticsEngine` stores Cutter authorization, the existing R2 observer shapes/stops it, `HapticsManager` immediately re-evaluates continuous state after authority-changing events, and `HapticMixer` renders a two-layer powered-tool waveform through the existing WASAPI continuous-state transport.

**Tech Stack:** C++20, CommonLibSF/SFSE integration, portable g++ regression binaries, xmake Windows build, WASAPI shared-event DualSense haptics.

**Spec:** `docs/superpowers/specs/2026-08-28-v0.2.47-cutter-continuous-haptics-design.md`

## Global Constraints

- Base is v0.2.46 Ballistic Family Haptics, already hardware-accepted.
- Cutter adaptive-trigger tuning remains unchanged.
- `FireMarkerBridge.h`, `EffectsEngine.cpp`, `HidWriteTrace.cpp`, trigger profiles, and Windows audio transport behavior remain frozen.
- R2 alone can never authorize Cutter haptics; only exact `weaponFireStart` while Cutter is equipped can authorize them.
- `r2 <= 12`, weapon swap, `GamePaused`, shutdown, and controller zero-clear stop Cutter continuous haptics immediately.
- Novablast and all discrete haptic families remain unchanged.
- Use TDD: every production behavior change must first be proven by a failing focused test.
- Imported workspace has no Git metadata; use test/review checkpoints instead of commits.
