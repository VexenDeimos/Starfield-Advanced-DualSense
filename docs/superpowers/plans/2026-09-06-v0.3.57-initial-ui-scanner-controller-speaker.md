# v0.3.57 Initial UI + Scanner Controller Speaker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote exactly five hardware-validated Starfield UI/scanner Wwise events into additive DualSense controller-speaker playback using installed game audio, with native-exact focus cadence and no diagnostic WEM extraction.

**Architecture:** Keep the existing Starfield `PostEvent` interception as the only Wwise hook. Extend the existing background Wwise preparation worker so it publishes five UI/scanner cues into a dedicated `UiSpeakerPreparedCache` before optional weapon preparation, then route exact production observations through a separate `UiSpeakerPlayback` into `ControllerSpeakerManager` under `SpeakerCategory::ScannerUI`. Preserve all existing weapon/VO/haptics/USB behavior and keep Starfield's original Wwise call authoritative.

**Tech Stack:** C++23, CommonLibSF/SFSE, Wwise metadata + BA2/WEM resolution, existing Wwise PCM/Vorbis decoder, XMake, Python source-regression tests, GCC/Clang portable tests, Windows/MSVC hardware gate.

**Spec:** `docs/superpowers/specs/2026-09-06-v0.3.57-initial-ui-scanner-controller-speaker-design.md`

## Global Constraints

- Target version is exactly `0.3.57`; runtime marker is exactly `0.3.57-initial-ui-scanner-controller-speaker`.
- Promote exactly: `0x05234A32 UIMenuGeneralFocus`, `0x5C8034FC UIMenuGeneralOK`, `0x7956E9B0 UIMenuGeneralCancel`, `0x12D8B183 UIMenuMonocleOpen`, `0x1F770B61 UIMenuMonocleClose`.
- Every promoted runtime observation requires `gameObjectId == 0x3` and zero external sources.
- Do not promote `0x06D80D5E UIItemFocus`, map rollover, Skills focus, mission-specific events, or other HUD candidates.
- `UIMenuGeneralFocus` uses native-exact cadence: no debounce, dedupe, replacement, cadence limiter, or held-stick special case.
- All five cues use `SpeakerCategory::ScannerUI` and `replaceExisting=false`.
- Effective production gate is `ControllerSpeaker=true AND SpeakerScannerUI=true`; behavior must not depend on `SpeakerWeapons` or `DebugLogging`.
- Reuse installed Starfield WEMs; no ESP/ESM/BA2/BSA and no bundled Bethesda audio.
- Production v0.3.57 performs no automatic UI WEM extraction.
- Original Starfield `PostEvent` executes exactly once with unchanged arguments/return value; UI playback is additive only.
- UI cue decode/preparation runs off the Wwise callback/game thread through the existing background preparation worker.
- One failed UI cue must not poison the other successfully prepared cues.
- Preserve the proven logical-mono-to-physical-Channel-2 USB speaker mapping unchanged.
- Haptics, adaptive triggers, lightbar, touchpad, TESHit, remote VO, weapon speaker behavior, and weapon persistent voices remain behaviorally unchanged.
- Package only changed/new files relative to accepted v0.3.56; never repackage the full source tree.
- Windows handoff must show `ProductVersion=0.3.57.0` and `FileVersion=0.3.57.0` before hardware acceptance.
