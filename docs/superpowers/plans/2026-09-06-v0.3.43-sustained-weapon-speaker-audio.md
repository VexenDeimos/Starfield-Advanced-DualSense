# v0.3.43 Sustained Weapon Speaker Audio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add lifecycle-correct, continuously looping DualSense controller-speaker audio for Arc Welder and Cutter while leaving every v0.3.42 finite weapon-speaker behavior unchanged.

**Architecture:** Extend the weapon-speaker catalog with an optional sustained cue, prepare Arc Welder/Cutter finite transients plus immutable loop PCM on the existing background weapon-audio worker, and add exactly one persistent prepared voice to `SpeakerMixer`. `WeaponSpeakerPlayback` remains the lifecycle authority: exact player-object Wwise Loop_Play starts the voice, exact Loop_Stop or a safety stop clears it, and raw R2 can only stop an already-authorized voice. The transport carries shared immutable PCM references rather than copying loop frame vectors on Starfield callback threads.

**Tech Stack:** C++23, xmake 3.x, CommonLibSF/SFSE, Windows WASAPI shared-event audio, Wwise/BA2/WEM resolver pipeline, Python source regressions.

**Spec:** `docs/superpowers/specs/2026-09-06-v0.3.43-sustained-weapon-speaker-audio-design.md`

## Global Constraints

- Baseline is StarfieldDualSense v0.3.42; target product/file version is exactly `0.3.43.0`.
- Runtime marker is exactly `0.3.43-sustained-weapon-speaker-audio`.
- Existing 44 v0.3.42 logical weapon-speaker profiles and their finite one-shot semantics remain behaviorally frozen.
- Final catalog totals are exactly 46 logical profiles, 43 physical families, and 444 physical prepared variants.
- Discovery stays inactive with exactly 0 targets.
- Arc Welder Loop_Play/Loop_Stop are exactly `0xBB87C268` / `0x46C5B7DA`, player object `0x2`.
- Cutter Loop_Play/Loop_Stop are exactly `0x8EDCB1C7` / `0x40FF9B15`, player object `0x2`.
- Raw R2 never starts persistent speaker audio; R2 `<= 12` is a stop-only safety input.
- Persistent audio has no fixed watchdog or duration cutoff.
- Opening `DataMenu`, `PauseMenu`, or `LoadingMenu`, `GamePaused`, weapon swap, backend stop, endpoint invalidation, and shutdown clear persistent audio and authorization.
- Closing a menu or reconnecting an endpoint never resumes stale persistent audio; a fresh exact Loop_Play is required.
- All WEM resolution, archive selection, decode, resample, and loop shaping happen on the existing `WeaponAudioPipeline` worker, never on a Wwise/gameplay callback.
- Normal Starfield audio is never stopped, reposted, suppressed, or replaced.
- Shared cross layers (`WPN_Cutter_Beam_Cross_*_LPM.wav`), Arc Welder reverb events `0xAE1D7B85` / `0x008D8D03`, Cutter reverb events `0x5F97D32A` / `0xB34A3F54`, and NPC/environment/impact media remain excluded.
- The source snapshot is not a Git repository. Do not initialize Git. At each task boundary, record the changed-file list and run the task's verification commands instead of creating a commit.
- Final handoff is a changed-files-only ZIP, matching the user's established StarfieldDualSense workflow.

```cpp
    PreparedSpeakerPcm& pcm,
    float gain,
    std::size_t crossfadeFrames,
    std::size_t& loopResumeFrame) noexcept
{
    try {
        loopResumeFrame = 0u;
        if (pcm.frames.size() < 2u) {
            return false;
        }
        pcm.gain = gain;
        const auto crossfade = (std::min)(crossfadeFrames, pcm.frames.size() / 2u);
        if (crossfade == 0u) {
            return false;
        }
        const auto tailStart = pcm.frames.size() - crossfade;
        const auto denominator = static_cast<float>(crossfade);
        for (std::size_t i = 0; i < crossfade; ++i) {
            const float headWeight = static_cast<float>(i + 1u) / denominator;
            const float tailWeight = 1.0F - headWeight;
            auto& tail = pcm.frames[tailStart + i];
            const auto head = pcm.frames[i];
            tail.left = tail.left * tailWeight + head.left * headWeight;
            tail.right = tail.right * tailWeight + head.right * headWeight;
        }
        loopResumeFrame = crossfade;
        return loopResumeFrame < pcm.frames.size();
    } catch (...) {
        loopResumeFrame = 0u;
        return false;
    }
}
```

This preserves frame count, performs no render-thread allocation, and causes later wraps to continue at frame 240 after the tail has already morphed through the first 240 source frames.
