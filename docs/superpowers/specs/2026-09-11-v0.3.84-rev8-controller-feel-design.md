# v0.3.84 REV-8 Controller Feel — Design

Date: 2026-09-11
Status: Approved design, awaiting written-spec review before implementation planning
Baseline: v0.3.83-r1 Boost-Armed Physics Correction

## Purpose

v0.3.84 is the first production controller-feedback layer for the REV-8. It converts the already hardware-validated land-vehicle authority, telemetry, action signatures, and boost-armed physics state into DualSense haptics and adaptive-trigger behavior.

The build must preserve the complete v0.3.83-r1 authority/physics baseline. It must not weaken the fail-closed ownership model, promote camera state into authority, use raw controller input as gameplay authority, or alter any accepted ship/on-foot behavior.

## Frozen v0.3.83-r1 Inputs

The following are treated as authoritative inputs and are not redesigned in v0.3.84:

- Tier-A REV-8 identity/authority comes from `PlayerCharacter -> currentProcess -> middleHigh -> occupiedFurniture`, validated as a furniture reference, while `RE::CameraState::kVehicle` is active only as corroboration/suppression context.
- Position-derived REV-8 telemetry supplies translational speed, vertical speed, and scalar acceleration.
- Accepted vertical boost is the hardware-validated Wwise event `0xF6A67354` while Tier-A authority is active.
- Jump physics is boost-armed. Terrain motion alone cannot arm AIRBORNE, DESCENDING, or TOUCHDOWN.
- Touchdown is physics-derived from accepted boost -> airborne -> descent -> settled vertical motion.
- Touchdown impact evidence is the peak downward vertical speed captured by the frozen physics probe.
- REV-8 gun identity is `VehicleFireWeapon` correlated with Wwise `0x3DD3DADD` under Tier-A authority.
- REV-8 slow-time/aim input identity is Starfield semantic `VehicleAim`.
- `0xDC42D80F` remains contact/suspension corroboration only.
- `0xA3BB6A5E` remains terrain-contact evidence and never authorizes touchdown.
- `LandVehicleContextEntered/Exited` remain suppression/lifecycle boundaries, not production-effect authority by themselves.

## Scope

v0.3.84 adds only:

1. Subtle continuous REV-8 driving/chassis haptics.
2. A finite boost-start haptic kick.
3. Airborne reduction of the normal driving bed.
4. Physics-scaled touchdown haptics.
5. Mounted-gun R2 resistance/recoil plus a finite haptic recoil kick.
6. L2 slow-time/aim resistance while `VehicleAim` is active.
7. Explicit land-vehicle production ownership/arbitration and hard-clear behavior.

Out of scope for this version:

- Controller-speaker REV-8 audio.
- REV-8-specific lightbar behavior.
- New vehicle discovery/recon.
- Changes to vehicle handling, game physics, game audio, or controls.
- Changes to frozen ship haptics/triggers.
- Changes to frozen on-foot weapon behavior.
- Synthetic timers that invent gameplay state.

## Architecture

### 1. Authority Boundary

Production REV-8 effects require **Tier-A land-vehicle authority**, not merely `kVehicle` or the existing suppression context.

The implementation should introduce an explicit production-facing authority lifecycle separate from `LandVehicleContextEntered/Exited`. A land-vehicle production owner may acquire only when the current `LandVehicleReconResult` reports proven vehicle identity and active Tier-A authority. It must release immediately on:

- occupied-furniture identity loss,
- authority epoch change,
- `LoadingMenu` invalidation,
- land-vehicle exit,
- ship-pilot takeover,
- shutdown.

`LandVehicleContextEntered` may continue clearing stale handheld ownership before Tier-A promotion, but must never install REV-8 trigger or haptic output on its own.

### 2. Continuous Motion State

Mirror the existing ship propulsion pattern instead of routing 10 Hz telemetry through generic `GameEvent` traffic.

Introduce a compact production state such as `LandVehicleMotionState` containing only controller-relevant trusted data:

- `authorityActive`
- `authorityEpoch`
- `speed`
- `acceleration`
- `airborne`
- `descending`

The adapter publishes this state from the existing 100 ms land-vehicle telemetry/physics poll after the frozen authority and telemetry probes have run. The continuous haptics consumer receives it through a dedicated method analogous to `HapticsManager::handleShipPropulsionState(...)`.

No consumer re-derives vehicle identity or velocity.

### 3. Discrete Production Semantics

Use explicit production semantics for finite actions rather than exposing raw Wwise or semantic-input observations directly to effects code. Expected semantics are conceptually:

- Land vehicle authority acquired/released.
- REV-8 boost started.
- REV-8 touchdown with normalized impact evidence.
- REV-8 gun fired.
- REV-8 aim/slow-time started/stopped.

The exact enum names can follow the repository's existing naming style, but the semantic separation is mandatory.

The plugin/adapter layer performs the validation/correlation; `EffectsEngine` and `HapticsManager` consume trusted semantics only.

## Controller Feel

### Base Driving — Approved Option A

The REV-8 has a light continuous chassis/engine texture while moving.

The feel model is deliberately **load-biased, not speed-biased**:

- Stationary idle is effectively or nearly silent.
- Low-speed movement introduces a faint chassis presence.
- Cruise speed raises the body only modestly.
- Acceleration/deceleration contributes more strongly than absolute speed.
- Real terrain acceleration may add subtle texture/modulation.
- Ordinary terrain motion never creates the finite boost or landing effects.

This avoids a controller that simply buzzes harder the faster the REV-8 travels.

Implementation should use bounded normalized telemetry terms and smooth the continuous target enough to avoid 100 ms stair-stepping. Tuning constants are presentation values only and must never participate in authority decisions.

### Boost Start

When the accepted `0xF6A67354` vertical-boost event occurs under current Tier-A authority:

- emit one strong, short boost-start haptic kick;
- arm/continue the already-frozen jump physics path exactly as v0.3.83-r1 does;
- do not create adaptive-trigger behavior for boost itself.

The boost kick is a finite overlay and must not replace the continuous chassis owner permanently.

### Airborne Feel

Once the frozen physics probe reaches AIRBORNE for the currently boost-armed jump:

- substantially reduce the normal REV-8 chassis bed;
- do not replace it with a synthetic constant "air" rumble;
- keep gun and L2 effects available if Starfield permits those actions while airborne.

The purpose is a perceptual reduction in vehicle weight while off the ground.

### Touchdown

Touchdown haptics are authorized only by the frozen boost-armed physics transition.

The touchdown effect is one finite heavy thump. Its gain/weight scales from `impactVerticalSpeed` captured by the physics probe:

- small valid landing -> modest bump,
- normal jump landing -> strong impact,
- hard landing -> strongest bounded impact.

The mapping must clamp safely and remain monotonic. No Wwise contact event authorizes the thump. `0xDC42D80F` may remain diagnostic corroboration only.

Touchdown has the highest REV-8 finite-haptic priority. After its finite effect completes, the continuous driving bed resumes from fresh live motion state rather than cached pre-impact output.

### Mounted Gun — R2 + Haptics

R2 is vehicle-owned only while Tier-A REV-8 authority is active.

Baseline behavior:

- install a firm but usable R2 resistance wall representing the mounted weapon;
- do not let stale on-foot weapon profiles coexist with it;
- raw physical R2 input alone cannot authorize recoil.

Confirmed shot behavior:

- require the frozen REV-8 firing identity (`VehicleFireWeapon` correlated with Wwise `0x3DD3DADD`) under current Tier-A authority;
- emit one finite adaptive-trigger recoil snap;
- emit one short mounted-gun haptic kick;
- restore the vehicle R2 baseline wall after the finite trigger effect expires.

The mounted-gun feel should be heavier and more mechanical than an on-foot rifle but materially lighter than the accepted ship-cannon presentation.

### Slow-Time / Aim — L2

`VehicleAim` owns L2 while Tier-A authority is active.

On aim activation:

- apply a smooth resistance ramp/detent;
- maintain deliberate resistance while `VehicleAim` remains active;
- avoid repeated finite haptic pulses.

On aim release:

- return L2 cleanly to neutral.

L2 slow-time and R2 gun ownership are independent and may coexist.

## Ownership and Arbitration

### Haptic Priority

REV-8 haptic composition uses this priority from highest to lowest:

1. hard clear / blocked context,
2. touchdown impact,
3. mounted-gun recoil,
4. boost-start kick,
5. continuous driving/chassis body.

Finite overlays do not destroy the continuous state. They layer over or temporarily dominate it, then retire. The continuous layer always resumes from the newest accepted motion state.

### Trigger Ownership

- R2: REV-8 mounted-gun baseline/recoil while Tier-A vehicle authority is active.
- L2: REV-8 slow-time resistance only while Tier-A authority and `VehicleAim` are active.
- Existing handheld profiles are suppressed for the entire land-vehicle context.
- Existing ship ownership takes precedence if ship-pilot authority appears.

### Blocking / Clear Rules

The following immediately neutralize REV-8 continuous haptics and both adaptive triggers:

- `LoadingMenu`,
- existing blocking menu policy used for production vehicle output,
- Tier-A authority loss,
- identity/epoch change,
- vehicle exit,
- ship-pilot takeover,
- shutdown.

Closing a menu or leaving a suppressed context must **not** restore cached REV-8 bytes. Reacquisition requires fresh current authority/state, mirroring the accepted ship/on-foot freshness rules.

## Interaction With Existing Systems

### HapticsManager

Extend the existing context-aware ownership model rather than adding an independent haptic thread or mixer.

Expected responsibilities:

- track Tier-A REV-8 production ownership,
- own the latest REV-8 continuous motion state,
- compose the subtle vehicle continuous bed,
- submit boost/gun/touchdown finite commands,
- clear all REV-8 ownership on the established safety boundaries.

Existing ship continuous composition remains untouched except where generic context arbitration needs to recognize that REV-8 owns the controller.

### EffectsEngine

Extend the existing persistent/transient trigger model.

Expected responsibilities:

- install the vehicle R2 wall only under Tier-A authority,
- apply finite R2 gun recoil only on trusted gun-fire semantics,
- apply/clear L2 `VehicleAim` resistance,
- hard-clear both on blocking/lifecycle boundaries,
- preserve all existing ship and handheld branches.

### GameStateAdapter / Plugin

The adapter remains the owner of authority, telemetry, and physics truth.

The plugin/native-observation layer remains the owner of Wwise/semantic correlation. It should emit production semantics only after authority checks. Raw input logging remains diagnostic/annotation behavior and does not become authority.

## Failure Behavior

Every ambiguous state fails closed:

- no proven REV-8 identity -> no REV-8 production output;
- stale authority epoch -> no output;
- unreadable telemetry -> clear/decay continuous motion, never invent velocity;
- boost Wwise event without current Tier-A authority -> no production boost;
- terrain/contact Wwise event without physics touchdown -> no landing thump;
- raw R2 without confirmed gun shot -> baseline wall only, no recoil;
- raw L2 without accepted `VehicleAim` -> no slow-time trigger state;
- loading/exit/ship takeover -> immediate neutral output.

## Testing Strategy

Implementation must be test-driven and preserve the frozen v0.3.83-r1 hardware model.

### Portable Unit Tests

Add focused tests for:

- land-vehicle continuous haptic mapping at idle, cruise, acceleration, braking/deceleration, rough terrain, airborne, and authority loss;
- smoothing/decay without stale-state resurrection;
- touchdown impact scaling monotonicity and clamping;
- boost-start finite effect uniqueness;
- mounted-gun haptic uniqueness per confirmed shot;
- R2 baseline/recoil/restore behavior;
- L2 aim activate/hold/release behavior;
- independent simultaneous L2 aim + R2 gun ownership;
- menu/loading/exit/ship-takeover hard clears;
- freshness requirement after clear/reacquisition.

### Regression Contracts

Retain and rerun:

- v0.3.83-r1 boost-armed physics tests,
- v0.3.83 Tier-A authority tests,
- v0.3.82 telemetry tests,
- v0.3.81 Wwise signature tests,
- v0.3.80-r2b land-vehicle handheld suppression tests,
- frozen v0.3.79-r2 ship launch/landing wall,
- accepted ship weapon/propulsion suites,
- accepted on-foot trigger/haptic ownership tests affected by shared arbitration.

Add source-level contracts proving:

- `kVehicle` remains corroboration-only;
- `LandVehicleContextEntered` remains insufficient for production output;
- raw controller input remains authority=no;
- contact events do not authorize touchdown;
- no REV-8 speaker/lightbar output is introduced in v0.3.84.

### Windows Gate

The Windows gate must:

1. run all new focused REV-8 production tests;
2. run the retained v0.3.83-r1 authority/physics wall;
3. run the retained ship/controller regression wall;
4. clean the plugin target before build;
5. build the DLL with MSVC;
6. verify built and installed ProductVersion/FileVersion for v0.3.84;
7. install the DLL only after all preceding checks pass.

No Windows-gate success is claimed until the user's actual Windows output confirms the final pass banner.

## Hardware Validation Plan

Hardware testing should be split so failures can be attributed cleanly.

### Pass 1 — Ownership + Base Driving

Verify:

- REV-8 entry replaces handheld output only after Tier-A authority is active;
- idle is nearly silent;
- normal movement produces the subtle approved Option-A chassis body;
- acceleration is more noticeable than steady cruise;
- rough terrain adds texture without large false impacts;
- exit restores no cached handheld state before fresh on-foot observations.

### Pass 2 — Boost + Touchdown

Verify:

- exactly one boost kick per accepted boost;
- airborne bed reduction is perceptible;
- exactly one landing thump per physics touchdown;
- harder measured impacts feel stronger;
- rough terrain without boost produces no landing thump.

### Pass 3 — R2 Gun + L2 Slow-Time

Verify:

- R2 has a stable mounted-gun wall in the REV-8;
- each confirmed shot produces one trigger snap and one haptic kick;
- holding/pulling R2 without a confirmed shot produces no false recoil;
- L2 gains smooth resistance only during `VehicleAim`;
- L2 and R2 work simultaneously;
- menus/loading/exit immediately neutralize both.

## Acceptance Criteria

v0.3.84 is accepted only when all of the following are true:

- v0.3.83-r1 Tier-A authority and boost-armed physics remain unchanged and pass retained tests.
- Normal REV-8 driving matches approved Option A: subtle at cruise, more expressive under load/terrain.
- Rough terrain never fabricates boost or touchdown effects.
- Accepted boost produces one finite kick and airborne reduction.
- Physics touchdown produces one impact-scaled thump.
- Confirmed mounted-gun fire produces exactly one R2 recoil snap and haptic kick per shot.
- Raw R2 never fabricates gun recoil.
- `VehicleAim` produces stable L2 resistance and release-to-neutral behavior.
- No stale REV-8 output survives menu/loading/exit/authority loss/ship takeover.
- No REV-8 speaker or lightbar behavior is added.
- Frozen ship and on-foot behavior remain regression-clean.
